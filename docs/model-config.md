# 模型配置编辑器

入口位于左上角应用选择框，选择“模型配置”。也可直接打开 `model-config/index.html`。

## 独立边界

`model-config/` 自带 HTML、CSS、状态与核心逻辑，不依赖主查看器或现场缺陷页面的业务模块、存储、工程状态。三个页面只通过 `shared/app-switcher.js` 导航。离开存在未另存修改的配置页时，浏览器会提示确认。

## 编辑方式

- 支持可选 `label_name` / `lable_name`：节点行展示、就地编辑、完整参数、搜索、复制子树及另存均保留该字段。新节点带空标签；旧节点缺少标签时仅显示空输入，不自动改写源内容，填写后才新增字段。

- 打开 JSON 后默认进入递归节点树，按照每个节点的 `childlist` 嵌套显示其子树。缩进和树枝线表示父子关系；节点前缀显示上级传入的 `last_output`（index）与 `label_name` / `lable_name`（label），不再展示层级编号。模型名、结果编码仍保留；名称或上级输出相同的节点仍是独立节点，不合并。
- 默认显示根节点和一级分支；一级分支只折叠自身，展开后可一次查看完整子树。“分支概览”随时恢复此视图，另有全部展开 / 收起、定位选中和搜索。搜索保留匹配节点的祖先链。
- 节点采用 32px 单行树形表格，上级 index、标签名称、模型 / 预处理、结果编码、数量、置信度、非缺陷标记直接显示为可编辑单元格，无需先选中。各列按表头和整份配置中该列最长内容自动测量宽度（含折叠节点），使用实际字体并预留输入框空间；输入时同步变宽，删除内容或撤销后重新计算。不用短字段强行填满屏幕，超宽内容在节点区横向滚动。统一表头在纵向滚动时固定。层级缩进每层 18px，仅作用于第一列，各深度的字段列始终对齐。主表和详细配置树的展开 / 收起三角为 20px，点击区域 26×28px，主表仍保持 32px 行高。长值悬停查看全文，窄屏可在节点区横向滚动。
- 文件中的其他节点字段自动生成扩展列，对象和数组以 JSON 单元格编辑。缺失字段显示“—”且不会自动补写；标签缺失时保留空输入，填写后才新增。两个标签拼写同时存在时分别编辑，保留原键及类型。
- 每行背景按可见顺序交替使用白色和浅蓝色；搜索、折叠、删除、排序后重新排列，不按父级单独重置。选中标记保留在左侧。
- 任意深度节点的字段均可直接编辑；跨行编辑保留其他行的无效输入，修正前阻止保存及重建树的操作。每行尾部可新增、复制、粘贴、删除、上移 / 下移、升一级 / 降一级、调整层级、展开全部后代和打开详细配置。
- 行尾“删除”只移除本节点，其直属子节点按原顺序接到原位置，整条下游链及后代保留；叶节点删除后其他同级自然顺次前移。详细配置保留独立的“删除整棵子树”，操作前明确确认。
- “⇤”升一级：携带后代移至原父节点后面；“⇥”降一级：携带后代成为前一个同级节点的末尾子节点。根节点不能上提，首个同级节点不能下沉；“层级”可选择任意目标，在目标前、后、子级或根列表末尾安放，排除自身及后代，防止循环。字段值不随层级自动改写。
- 节点左侧点阵手柄可直接拖动整棵子树；停在目标行上缘插入其前、中央成为其末尾子节点、下缘插入其后。有效落点在目标行高亮并显示位置提示；拖到顶部“＋ 根节点”可移至根列表末尾。自身、后代及无效位置不会接受放置。手柄可用 Tab 聚焦，按回车或空格打开精确层级选择。
- “复制”只将单节点快照放到页面剪贴板，childlist 为空，不立即修改配置。然后在目标行点“粘贴”，选择同级前 / 后、末尾子节点或插为父节点；插为父节点时，原目标及其后代完整接在复制节点下面。也可在顶部粘贴到根列表；复制内容可重复插入，打开新文件清空剪贴板。详细配置另外保留复制整个子树到剪贴板及复制分支到下一项。
- 删除上提、层级移动、单节点粘贴均为一次可撤销修改；移动在临时副本中校验，失败不产生半完成的删除，也不破坏撤销 / 重做历史。结构改变后重建分支概览并展开选中节点的祖先，避免旧数组路径折叠错误对象。
- 点击节点右上角 `↗` 或顶部“详细配置”，按需打开完整编辑面板；“相机 / 线路”直接打开全局配置。面板保留扩展字段、文件信息、JSON、修改对照与另存操作，关闭后回到节点树。
- 节点参数保留原类型、空值、编号前导零和未知字段。可新增、复制、删除、排序及调整层级，撤销或重做最近 100 步。
- `num` 的业务含义未从配置文件得到明确说明，因此不根据子节点数量自动调整；界面提示手动维护。
- “完整 JSON”可编辑任意字段，应用前校验语法、重复键和基本结构。未应用文本或无效字段会阻止另存及切换编辑对象。
- “修改对照”始终与最初打开的源内容比较，数组按位置比较。另存不会重置源文件基准。

## 编码与源文件保护

源文件仅通过 `File.arrayBuffer()` 读取；编辑过程完全在内存中，不持有源文件的可写句柄。

支持严格解码的 UTF-8、UTF-16 LE/BE，分别识别并保留有 / 无 BOM 状态；不支持或不能可靠识别的编码拒绝导入，绝不静默转换。无 BOM 的 UTF-8 输出不会添加 BOM。保留源换行习惯。普通字段编辑通过语法位置只替换对应值，未改动的空白、转义、数值字面量不重新序列化；未修改直接另存时输出逐字节一致。完整 JSON 编辑会保留用户文本，换行归一到源文件的换行方式。

另存要求 Edge / Chrome 的 `showDirectoryPicker`（推荐 localhost 或 HTTPS）。先填写与源文件不同的新文件名，再选择目标目录。已有文件名、源文件名、非法路径及保留名称会被拒绝。仅在目标不存在时创建新文件，并直接写入编码后的 `Uint8Array`。浏览器不支持目录选择时停止另存，不退化成可能覆盖源文件的下载流程。

浏览器文件系统 API 不提供跨进程的原子“仅不存在时创建”选项：存在检查与创建之间，其他程序仍可能同时创建同名目标。默认输出名包含时间以降低冲突；禁止源文件同名的校验始终在写入之前执行。
